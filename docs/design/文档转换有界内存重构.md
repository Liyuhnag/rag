# 文档转换与产物收集的有界内存重构

日期：2026-10-27。状态：实现完成，工作分支测试通过，未部署。

## 目标与决策

保留“上传源文件到 S3 → 按需转换 → 解析产物写回 S3 → 后续流式切块”的流程，消除 Python 主链路把源文件、所有分段 ZIP、全文字符串和编码字节同时持有的行为。

采用临时文件和有限缓冲。ZIP 需要随机访问，XLSX 还需要共享字符串索引与后续扩展表头；单纯把 read() 换成生成器无法消除这些状态。将大内容和表格索引移到磁盘，S3/HTTP 上传下载采用分块传输。没有增加第三方依赖。

## 当前数据流

```text
本地格式：S3 下载 → TXT/MD/CSV/XLSX iter_blocks
        → 单遍写 merged.md / merged.json 临时文件
        → upload_file → manifest → 数据库产物指针

PDF/Word：下载本地文件 → PDF 按页拆分（Word 保持大小限制）
        → MinerU 流式 multipart 上传 → 异步轮询
        → 流式下载 result.zip → 文件上传 S3
        → 只收集 result_key → 逐段下载/解压到临时文件
        → 按页合并、图片路径改写 → 文件上传 S3
        → manifest → 数据库产物指针
```

`ParsedDocument.blocks` 为 Iterable，生产本地解析由 DocumentParsingService 选择 iter_blocks，消费一次。旧 parse/parse_bytes 保留作为小文件兼容接口，仍可能全量分配，不能用于大文件生产编排。生产任务不再调用这些兼容路径。

## 产物契约

S3 原文件、分段及最终产物 key 保持原约定。MinerU 合并 Markdown 仍按 `(page_start, part_index)` 排序；清单 parts 保留输入顺序。图片相对链接改写到 assets/part-N，原分段 Markdown 保留原始字节，合并正文严格 UTF-8 解码、去 BOM。

Markdown 块携带 `metadata.verbatim=true`，序列化按原文拼接。TXT 长段后续碎片携带 `metadata.continuation=true`，不会插入段间空行。JSON 块保留 locator、metadata，供后续切块识别续片和表格位置。

CSV 每行输出一个单元素 JSON 数组块；XLSX 每批最多 128 行。merged.md 因此可能包含多个用空行分隔的 JSON 数组，不再保证整张表对应一个大数组。merged.json 仍是合法 JSON 对象及 blocks 数组，按块增量写入。未来切块不能把整个 Markdown 当作单一 JSON 数组解析。

CSV metadata.row_count 表示整表数据行数；XLSX 表示当前块行数。column_count 均为最终表头宽度。

## 内存与磁盘边界

- 文本读取块：65,536 字符；TXT 超长段落分片，连续空白超过 65,536 字符明确拒绝。
- CSV 逻辑记录：最多 1,048,576 字符；保留标准库 CSV 字段大小限制及原行数/单元格数限制。两遍扫描确定最终动态表头。
- XLSX 使用 ZIP/XML 增量解析和 SQLite 临时索引，SQLite page cache 约 2MiB；输出批次和单行约 1Mi 字符。保留合并单元格、共享字符串、缓存公式和日期规范化。XML 文本 run 和子树有上限；拒绝 DTD/ENTITY、当前不支持 UTF-16 XML。在 ZipFile 打开前预检中央目录（16MiB、10,000 条目、2GiB 包体），拒绝 ZIP64/分卷；索引仍占用额度内与成员数相关的内存。
- MinerU 上传/下载以 64KiB 缓冲处理。上传重试重新打开源文件，下载失败清理半成品，成功原子替换本地目标；JSON 响应有 1MiB 限制。
- MinerU 单分段 ZIP 最多 2GiB，中央目录最多 16MiB、10,000 条目；实际读取的允许成员解压数据累计最多 1GiB。拒绝分卷和 ZIP64。普通长 Markdown 行可处理，未完成图片链接候选超过 1Mi 字符拒绝。
- S3 文件上传关闭传输线程并限制并发；小型 manifest 仍直接 bytes 上传。
- 临时目录正常完成、异常和生成器关闭时清理。进程被强杀时 TemporaryDirectory 无法保证清理，部署需要临时盘清理策略和容量监控。

磁盘不是常量开销：本地格式需要源文件、产物，XLSX 还需要 SQLite 索引；MinerU 收集会暂存所有已验证成员、渲染段和合并文件。应为 Worker 配置真实磁盘目录和空间预算，避免使用容量计入容器内存的 tmpfs。PDF 的 PyMuPDF 原生分段内存仍取决于文档结构，本次不声称外部解析器/原生库任意输入常量内存。

## 失败与一致性

读取分段、校验和合并均在受控错误范围内，读取失败不会再绕过异常处理留下 MERGING。发布/标记文档失败带 expected_version 条件，旧任务不能覆盖新版本指针/状态。begin_parse 不允许版本倒退。

所有输入验证完成后才上传合并产物，总 manifest 最后写，数据库指针在上传成功后更新。但固定版本 key 的多个 S3 对象并非原子事务；同一版本重新覆盖期间仍可能看到部分对象。数据库任务完成、各分段状态和文档指针也未改成一个事务。进程在 MERGING 阶段被强杀后的自动租约恢复属于现有任务调度缺口，需要单独补齐，不能把本次异常处理修复等同于完整故障恢复。

## 实测

使用 tests/bench_conversion_memory.py，在独立 Python 子进程比较基线提交 a9b8818 的旧 collect 与新 collect；4 个压缩分段、中文正文、磁盘假对象存储，无真实 S3/MinerU。32MiB 和 128MiB 是解压后的正文总量。RSS 包含 Python 解释器和导入成本，耗时不含输入夹具构造。

| 正文总量 | 旧峰值 RSS | 新峰值 RSS | 旧耗时 | 新耗时 |
| --- | ---: | ---: | ---: | ---: |
| 32MiB | 209.74MiB | 73.24MiB | 0.582s | 0.714s |
| 128MiB | 607.64MiB | 73.18MiB | 1.313s | 1.490s |

同一输入的新旧 merged.md SHA-256 一致。128MiB 样本峰值 RSS 下降约 88%。这是受控本地合并实验，不代表真实 Worker 并发、网络和原生解析库的端到端峰值。

TXT/Markdown 输入从 1MiB 增到 16MiB 的 tracemalloc 峰值分别约 0.83MB、0.3MB；CSV 从 1,000 行增至 100,000 行约 0.09MB→0.27MB；XLSX sharedStrings 从 1,000 行增至 20,000 行约 0.52MiB→0.43MiB。这些只统计 Python 分配，不是 RSS。

回归覆盖流式编排、产物兼容、UTF-8/空白跨缓冲、图片跨行/跨块、ZIP 安全限制、上传下载重试、临时文件清理、表格规范与版本 SQL 条件。真实 MinerU/S3 联调和生产部署尚未执行。

最终验证：后端完整测试 183 项通过；Ruff、编译检查、git diff --check 通过。独立审查指出的缺省 Excel 坐标覆盖、rPh 注音污染、ZIP 目录校验过晚均已补回归并修复。
