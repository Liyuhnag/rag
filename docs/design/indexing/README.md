## 1. 文档集说明

本目录是 RAG 文档索引阶段的正式设计文档集，覆盖从用户上传文件到文档可被向量和关键词双路检索的完整链路。

文档集采用“总体设计 + 子模块详细设计”的结构：

- 总体设计定义阶段边界、全局数据模型、状态机、部署约束和跨模块契约；
- 子模块详细设计定义接口、表结构、算法、异常处理、配置和验收标准；
- 子模块之间的接口以总体设计为准；字段和实现细节以子模块为准。

本阶段不包含最终答案生成、对话 UI、rerank 模型和用户权限体系。这些内容在后续阶段单独设计。

## 3. 阅读顺序

建议按以下顺序阅读和评审：

1. 先读总体设计，确认阶段边界、数据模型和部署方案；
2. 再读大文件上传和文档解析，确认输入和中间产物；
3. 然后读向量化和 Elasticsearch 索引，确认双写一致性和检索契约；
4. 最后对照各文档的验收标准、风险表和评审记录提出意见。

## 4. 评审与变更流程

1. 文档编制完成后提交研发团队评审；
2. 评审意见记录在各文档的“评审记录”章节；
3. 编制人根据评审意见修订文档，更新修订记录和版本号；
4. 评审通过后版本升级为 V1.0，作为实施基线；
5. 实施过程中如需变更接口、表结构或状态机，必须同步更新受影响的文档，并在修订记录中说明原因。

## 5. 适用范围与约束

- 单文件上限约 300MB；
- MinerU 部署在独立 GPU 机器，通过内网 HTTP API 访问；
- Milvus、Elasticsearch、MySQL、Redis、SeaweedFS 与后端同机部署；
- embedding 使用阿里云 DashScope `text-embedding-v4`，默认 1024 维；
- Elasticsearch 使用 8.x 单节点并安装 IK 分词插件；
- 当前系统没有用户认证，生产部署前必须补齐认证和上传会话归属。
