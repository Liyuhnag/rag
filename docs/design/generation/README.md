## 1. 文档集说明

本目录是 RAG 文档生成阶段的正式设计文档集，覆盖从用户问题到带引用答案的完整链路：

```text
用户问题
  -> 会话历史加载
  -> 查询理解与改写（指代消解 / 拆解 / 过滤抽取）
  -> 调用检索阶段（多查询）
  -> 证据选择与上下文组装
  -> 大模型生成（流式）
  -> 引用解析与校验
  -> 带引用的答案 / 明确拒答
  -> 会话持久化与效果观测
```

生成阶段依赖前两个阶段的产物：

- 索引阶段（RAG-IDX）：MySQL 父块/子块、ES 子块索引、Milvus 子块向量；
- 检索阶段（RAG-RET）：`RetrievalService.search` 返回的 Top-k 父块和 `matched_children`。

生成阶段不修改索引和检索数据，只负责"把证据讲成答案"。

## 3. 阅读顺序

建议按以下顺序阅读和评审：

1. 先读总体设计，确认生成阶段边界、接口契约、数据模型和降级策略；
2. 再读查询理解和上下文组装，确认"问什么、拿什么喂给模型"；
3. 然后读答案生成和引用校验，确认"怎么答、答得有没有依据"；
4. 最后读可观测与评估，确认"怎么衡量好坏、怎么持续优化"。

## 4. 评审与变更流程

1. 文档编制完成后提交研发团队评审；
2. 评审意见记录在各文档的"评审记录"章节；
3. 编制人根据评审意见修订文档，更新修订记录和版本号；
4. 评审通过后版本升级为 V1.0，作为实施基线；
5. 实施过程中如需变更接口、Prompt 或降级策略，必须同步更新受影响的文档，并在修订记录中说明原因。

## 5. 适用范围与约束

- 生成粒度：检索证据是父块，答案引用到父块和命中子块；
- 默认模型为阿里云 DashScope `qwen-plus`，可通过配置切换；
- 默认流式输出（SSE），同时支持一次性 JSON 返回；
- 查询改写失败回退原始问题，不阻塞主链路；
- 回答必须基于检索证据，无依据时明确拒答；
- 引用必须可解析、可追溯，校验失败要标记而不是静默通过；
- 查询、对话历史和证据正文会发送到阿里云，按前两个阶段的合规要求处理；
- 当前系统没有用户认证，会话归属字段预留但暂不校验。
