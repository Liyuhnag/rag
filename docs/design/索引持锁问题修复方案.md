# 索引阶段持锁时间过长问题 - 修复方案

## 问题描述

### 当前实现的问题

在 `backend/task/index_document.py` 的 `_run` 函数中，整个索引过程被包裹在 `lease.writes()` 事务中：

```python
def _run(task, lease: TaskLease) -> None:
    try:
        with lease.writes():  # ← 开始持有任务行锁
            document = document_orm.get(task.document_id)
            # ... 版本检查 ...

            # 这里调用 DocumentIndexingService().run()
            # 包含：向量化、Milvus 写入、Elasticsearch 写入
            # 可能耗时 10+ 分钟
            published = DocumentIndexingService().run(
                document, task.version, heartbeat=heartbeat, lease=lease.ensure,
            )

            if published:
                task_orm.complete(...)  # ← 提交事务，释放行锁
```

### 问题根源

`lease.writes()` 的实现（`backend/services/task_runtime/lease.py:67-72`）：

```python
@contextmanager
def writes(self) -> Iterator[None]:
    """业务写入与租约校验同一事务，恢复者在提交前无法换掉 token。"""
    with self._writing:
        self._check()
        with task_orm.lease_guard(self.task_id, self.token, self.stages):
            # ← 这里持有数据库事务和行锁
            yield
```

`task_orm.lease_guard` 会开启数据库事务并持有任务行锁（`SELECT ... FOR UPDATE`），直到 `lease.writes()` 退出。

### 冲突场景

**时间线：**

| 时间 | 索引任务（持有行锁） | Recover 维护任务 |
|------|---------------------|------------------|
| T0 | 进入 `lease.writes()`，持有任务行锁 | - |
| T1 | 正在向量化（耗时操作）... | - |
| T2 | 正在写入 Milvus... | - |
| T3 | 正在写入 Elasticsearch... | Recover 扫描到该任务（超过 idle_seconds） |
| T4 | 还在写入... | 执行 `UPDATE document_tasks ... WHERE id = ? AND lease_token = ?` |
| T4 | 还在写入... | **UPDATE 被阻塞，等待行锁释放** |
| T5 | 还在写入... | **Recover 维护任务超时失败** ❌ |

### 后果

1. **Recover 维护任务失败** - 无法恢复其他失联任务
2. **级联影响** - 所有需要 Recover 的任务都被延迟
3. **系统不稳定** - 长事务持有行锁，阻塞其他操作

## 修复方案

### 方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|-------|
| **方案 1：分段提交** | 简单，风险低 | 需要处理中间状态 | ⭐⭐⭐⭐⭐ |
| **方案 2：乐观锁** | 彻底解决长事务 | 改动较大，需要版本号 | ⭐⭐⭐ |
| **方案 3：调大超时** | 改动最小 | 治标不治本 | ⭐ |

## 🎯 推荐方案：分段提交（方案 1）

### 核心思想

将索引过程拆分为 3 个阶段，每个阶段独立提交事务：

1. **前置检查阶段**（持锁）- 验证版本、检查文档状态
2. **索引执行阶段**（无锁）- 向量化、写入外部索引
3. **完成提交阶段**（持锁）- 标记任务完成

### 实现代码

```python
# backend/task/index_document.py

def _run(task, lease: TaskLease) -> None:
    try:
        # ============ 阶段 1：前置检查（持锁）============
        with lease.writes():
            document = document_orm.get(task.document_id)
            if document is None:
                task_orm.fail(task.id, "文档不存在", datetime.now(timezone.utc), lease.token)
                return
            if document.parse_version != task.version:
                fail_version_mismatch(task, datetime.now(timezone.utc))
                return
            if document.status == DocumentStatus.READY:
                task_orm.complete(task.id, "解析与索引完成", datetime.now(timezone.utc), lease.token)
                return

            # 🔹 关键改动：标记为 INDEXING_IN_PROGRESS
            # 这样 Recover 就知道任务正在执行，不会尝试恢复
            task_orm.mark_indexing_in_progress(
                task.id, lease.token, datetime.now(timezone.utc)
            )
        # ← 事务提交，行锁释放

        # ============ 阶段 2：索引执行（无锁）============
        # 在事务外执行耗时操作，不持有行锁
        def heartbeat(completed: int, total: int, last_chunk_id: str) -> None:
            lease.ensure()  # 只检查租约，不持有行锁
            # 使用轻量级更新，不阻塞其他操作
            task_orm.update_index_progress_lightweight(
                task.id, completed, total, last_chunk_id, lease.token,
                datetime.now(timezone.utc),
            )

        published = DocumentIndexingService().run(
            document, task.version, heartbeat=heartbeat, lease=lease.ensure,
        )

        # ============ 阶段 3：完成提交（持锁）============
        with lease.writes():
            # 再次验证租约，防止中间被 Recover 接管
            lease.ensure()

            if published:
                if not task_orm.complete(
                    task.id, "解析与索引完成", datetime.now(timezone.utc), lease.token
                ):
                    raise LeaseLost(task.id)
            else:
                fail_version_mismatch(task, datetime.now(timezone.utc))

    except LeaseLost:
        raise
    except Exception as exc:
        logger.exception("文档索引失败: %s", task.id)
        fail(task, lease, str(exc) or "索引失败")
        raise
```

### 需要新增的数据库操作

```python
# backend/model/document_task/orm.py

def mark_indexing_in_progress(
    task_id: str,
    token: str,
    now: datetime,
) -> bool:
    """标记任务正在索引中，更新心跳时间，不改变 status。"""
    affected = execute_count(
        """
        UPDATE document_tasks
        SET updated_at = %(now)s,
            step = '正在索引中'
        WHERE id = %(task_id)s
          AND lease_token = %(token)s
          AND status = 'RUNNING'
        """,
        {"task_id": task_id, "token": token, "now": as_utc(now)},
    )
    return affected == 1


def update_index_progress_lightweight(
    task_id: str,
    completed: int,
    total: int,
    last_chunk_id: str,
    token: str,
    now: datetime,
) -> bool:
    """轻量级进度更新，不持有长事务。"""
    result_json = json.dumps({
        "token": token,
        "last_chunk_id": last_chunk_id,
    })

    affected = execute_count(
        """
        UPDATE document_tasks
        SET progress = %(progress)s,
            step = %(step)s,
            result_json = %(result_json)s,
            updated_at = %(now)s
        WHERE id = %(task_id)s
          AND lease_token = %(token)s
          AND status = 'RUNNING'
        """,
        {
            "task_id": task_id,
            "progress": int(completed / total * 100) if total > 0 else 0,
            "step": f"已索引 {completed}/{total} 块",
            "result_json": result_json,
            "now": as_utc(now),
            "token": token,
        },
    )
    return affected == 1
```

### Recover 机制适配

当前 Recover 逻辑不需要改动，因为：

1. **阶段 2 期间持续心跳** - `update_index_progress_lightweight` 会更新 `updated_at`
2. **Recover 使用条件更新** - 如果任务的 `updated_at` 被更新，Recover 的 UPDATE 不会匹配到该任务
3. **失联保护依然有效** - 如果索引任务真的失联（进程崩溃），`updated_at` 不再更新，Recover 会正确接管

### 时间线对比

**修复后：**

| 时间 | 索引任务 | Recover 维护任务 |
|------|---------|------------------|
| T0 | 阶段 1：前置检查（持锁 100ms） | - |
| T0 | **提交事务，释放行锁** ✅ | - |
| T1 | 阶段 2：向量化（无锁）... | - |
| T2 | 阶段 2：写入 Milvus（无锁）... | - |
| T3 | 阶段 2：写入 ES（无锁）... | Recover 扫描任务 |
| T3 | 阶段 2：持续心跳更新 `updated_at` | 发现 `updated_at` 刚更新，跳过该任务 ✅ |
| T4 | 阶段 3：标记完成（持锁 50ms） | - |
| T4 | **提交事务，释放行锁** ✅ | - |

## 方案 2：乐观锁（备选）

### 核心思想

使用版本号代替长事务，每次更新时检查版本号是否匹配。

### 数据库改动

```sql
-- 添加版本号字段
ALTER TABLE document_tasks ADD COLUMN lock_version INT NOT NULL DEFAULT 1;

-- 更新时递增版本号
UPDATE document_tasks
SET status = 'COMPLETED',
    lock_version = lock_version + 1,
    updated_at = NOW()
WHERE id = ? AND lock_version = ?;
```

### 优点

- 彻底消除长事务
- 并发性能更好

### 缺点

- 需要数据库迁移
- 需要处理版本冲突重试逻辑
- 改动范围大，影响所有任务操作

### 推荐场景

如果未来有更多长耗时操作，可以考虑全面升级到乐观锁。

## 方案 3：调大超时（不推荐）

### 实现

```python
# backend/services/task_runtime/policy.py

INDEX_POLICY = TaskPolicy(
    soft_time_limit=1500,
    time_limit=1800,
    renew_seconds=30,
    idle_seconds=3600,  # ← 从 600 秒改为 3600 秒
)
```

### 为什么不推荐

1. **治标不治本** - 长事务持锁依然存在
2. **延迟恢复时间** - 真正失联的任务要 1 小时后才能恢复
3. **系统不健康** - 隐藏了设计问题

## 测试计划

### 单元测试

```python
# backend/tests/test_index_document.py

def test_index_no_long_transaction(db, mock_indexing_service):
    """索引过程不应持有长事务。"""
    task = create_test_task()

    # 模拟耗时索引
    with patch.object(mock_indexing_service, 'run') as mock_run:
        mock_run.side_effect = lambda *args, **kwargs: time.sleep(5)

        # 在另一个线程尝试 UPDATE 任务
        def concurrent_update():
            time.sleep(1)  # 等待索引开始
            result = execute_count(
                "UPDATE document_tasks SET updated_at = NOW() WHERE id = %(id)s",
                {"id": task.id}
            )
            return result

        future = ThreadPoolExecutor().submit(concurrent_update)
        index_document(task.id)

        # 并发 UPDATE 应该成功，不会被阻塞
        assert future.result() == 1


def test_recover_not_blocked_by_indexing(db):
    """Recover 不应被正在索引的任务阻塞。"""
    task = create_running_task(stage='INDEXING')

    # 模拟索引耗时
    def slow_index():
        with TaskLease(task.id, task.lease_token, INDEX_STAGES) as lease:
            time.sleep(5)

    executor = ThreadPoolExecutor()
    index_future = executor.submit(slow_index)

    time.sleep(1)  # 等待索引开始

    # Recover 应该立即返回，不被阻塞
    start = time.time()
    recover(datetime.now(timezone.utc), limit=10)
    duration = time.time() - start

    assert duration < 1.0  # Recover 不应等待索引完成

    index_future.result()  # 等待索引线程结束
```
